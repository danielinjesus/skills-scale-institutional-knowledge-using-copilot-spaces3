# OctoAcme Project Management Docs

Welcome to the central hub for OctoAcme's project management process documentation. This README helps you quickly find the right guide for your role and understand how we run projects at OctoAcme.

## Overview

OctoAcme manages projects with five core principles:

- **Customer-first** – prioritize customer value and usability in every decision.
- **Iterative delivery** – deliver small, testable increments to reduce risk and gather feedback early.
- **Clear ownership** – each project has a named Project Manager (PM) and Product Lead accountable for outcomes.
- **Data-informed decisions** – measure impact and iterate based on evidence.
- **Psychological safety** – encourage open feedback, experimentation, and learning from failure.

These principles guide everything from project initiation through retrospective, ensuring consistent, high-quality delivery across all cross-functional teams.

## Getting Started by Role

### Project Managers
1. Start with the [Project Management Overview](octoacme-project-management-overview.md) to understand the full delivery lifecycle.
2. Use the [Project Initiation Guide](octoacme-project-initiation.md) when kicking off a new project.
3. Refer to [Project Planning](octoacme-project-planning.md) for sprint setup and backlog management.
4. Track delivery health with [Execution & Tracking](octoacme-execution-and-tracking.md).
5. Manage risks proactively using [Risk Management & Communication](octoacme-risks-and-communication.md).
6. Close each cycle with [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md).

### Developers
1. Read the [Roles and Personas](octoacme-roles-and-personas.md) to understand your responsibilities and how you collaborate with PMs and Product Managers.
2. Review [Project Planning](octoacme-project-planning.md) to understand sprint structure, acceptance criteria, and Definition of Done.
3. Consult the [Release & Deployment Guide](octoacme-release-and-deployment.md) before deploying any changes.
4. Participate in retrospectives using [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md).

### Product Managers
1. Start with the [Project Management Overview](octoacme-project-management-overview.md) to align on shared processes.
2. Use the [Project Initiation Guide](octoacme-project-initiation.md) to define outcomes and success criteria at project start.
3. Collaborate on prioritization during [Project Planning](octoacme-project-planning.md).
4. Stay informed on risk and stakeholder communication via [Risk Management & Communication](octoacme-risks-and-communication.md).

## How to Use & Maintain These Docs

### Keeping Docs Updated
- Documentation should be updated whenever a process changes. Open a pull request with your proposed changes and request review from the relevant team lead.
- Use the issue template for process doc updates (`.github/ISSUE_TEMPLATE/`) to track proposed changes before implementing them.
- All updates should be reviewed and approved before merging to ensure accuracy and consistency.

### Integration with Copilot Spaces
These docs are designed to work with **GitHub Copilot Spaces**. When added to a Copilot Space, team members can ask Copilot questions about OctoAcme's processes and receive answers grounded in this documentation. To get the most value:

- Add all documents in this `docs/` folder to your Copilot Space.
- Keep documents up to date so Copilot's answers remain accurate.
- Use Copilot to onboard new team members by pointing them to the Space for Q&A.

### Requesting Process Doc Updates
If you identify a gap or need a process change, open an issue using the process doc update issue template. This ensures changes are discussed, reviewed, and documented consistently before being merged.
